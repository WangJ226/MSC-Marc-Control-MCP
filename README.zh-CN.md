## 从一次具体的分析任务开始

模型已经有了，输入文件却需要反复核对；求解中断后，要在日志里寻找线索；结果算完，还要逐个提取节点历史和曲线。Marc Control MCP 面向这些日常工作，让你在自己的 AI 客户端中提出任务，通过 MCP 调用本机工具，并查看实际返回的文件和检查记录。

你负责工程目标、模型假设与操作批准；AI 助手组织对话和工具调用；Marc/Mentat 执行相应模型操作与求解。适合已有 Marc 使用基础的土木、机械等领域研究人员、学生和工程用户。

## 三个适合开始的场景

**检查一个已有模型。** 提供脱敏 DAT 副本，请 AI 汇总材料、集合和接触相关检查项。先看审计结果，再决定是否生成修改候选。

**理解一次求解中断。** 提供日志与对应输入，汇总退出信息、增量进度及可定位的热点。将诊断当作排查线索，结合模型假设逐项确认。

**整理一组已有结果。** 明确 T16/CSV 文件、节点或变量、坐标方向和单位，提取所需历史或极值，核对曲线及输出文件。这样可以把重复提取过程交给工具，把精力留给结果解释。

## 一句话开始，一个结果验证

将文件路径、节点和变量换成自己的内容；AI 应先核对工具输入条件。

> **检查模型：** 只读审计我指定的 DAT 副本，汇总材料和集合归属、接触相关待核查项，列出依据与下一步建议。

> **排查求解：** 读取这次运行的日志，说明最后完成的增量、退出信息及可定位的异常线索，先给我诊断摘要。

> **提取结果：** 先清点这个 T16 文件的可用变量，再提取我指定节点与方向的历史，保存输出并说明单位和数据来源。

涉及变更、启动或求解时确认操作；完成后打开实际输出复核。[更多能力与输出说明 →](docs/features.md)

## 怎样用起来

**安装 → 激活 → 查找 Marc → 连接 AI → 环境检查 → 第一个小任务**

1. 查看 [Releases](https://github.com/WangJ226/Marc-MCP-Assistant/releases) 的可用安装包；当前公开列表为空时，通过 [联系入口](docs/contact.md) 获取体验安排。
2. 安装 EXE，按提供方给出的激活码或兑换码完成在线授权。使用期限以实际授权为准，体验申请由人工批准。
3. 自动查找 Marc，确认安装版本，执行环境检查。
4. 选择 WorkBuddy、Codex 或 Claude Desktop，完成配置后重载客户端并确认信任。
5. 复制软件提供的首次提示词，先调用环境检查，再选择项目副本开展一个小任务。
6. 对建模修改、启动与求解逐项确认；查看返回状态与实际输出，保留有效记录。

首次提示可以这样写：

> 请先调用 run_mcp_doctor 检查 Marc MCP 环境，汇总通过项和待处理项。随后只读检查我指定的项目副本。需要修改模型、启动 Mentat 或求解时，先说明操作、目标目录和预期输出，等待我确认。

## 安装要求与使用边界

- 准备 Windows、已安装且有有效许可证的 Marc/Mentat，以及已登录的 AI 客户端。MCP 自身 Python 运行环境随安装包提供。
- Marc 2016–2025 是适配目标范围，2024/2025 为优先使用版本；不同版本、许可证与主机组合需要实际验证。
- 自动配置覆盖 Marc 发现及客户端接入设置。Marc 安装、组织许可证、AI 登录和信任确认由使用者完成。
- 模型与结果保存在本机。发送给 AI 的提示、工具返回和文件内容按所选 AI 服务的数据政策处理，敏感项目先确认分享范围。
- 工程假设、单位、边界条件、收敛和结论由使用者复核。请从项目副本与小任务开始。
